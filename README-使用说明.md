# 骗子酒馆 α版 Liar's Bar · 局域网 / 远程联机版（v2）

> **α版说明**：这一版是参考《Liar's Bar》纸牌模式做的**魔改版**，规则和原作不完全一样
> （加了过牌、两圈作废、判断正确者先出、胜场榜、观战等）。
> 具体以 App 内的「📖 游戏规则」为准，别拿原作规则对照。

> 这一版把原来"Spring Boot + 浏览器"的工程，重做成了**一套零依赖的纯 Java 服务端**，
> 同一份代码既能打成**电脑上直接跑的服务端 JAR**，也能塞进**安卓 APK**里让手机自己当主机。
> 支持 2~4 人、局域网联机、以及用樱花映射做远程联机。

## 一、一分钟上手

### 方式 A：电脑当主机（**远程联机推荐这个**）

```powershell
# JDK 11 以上都行，本机已有 jdk-21.0.8
& "C:\Program Files\Android\openjdk\jdk-21.0.8\bin\java.exe" -jar "liarbar-server.jar"
```

启动后终端会打印两个地址：

```
本机访问 : http://127.0.0.1:8080/
局域网   : http://192.168.x.x:8080/     (同一 WiFi 的朋友用这个)
```

### 方式 B：手机当主机

把 `liarbar.apk` 装到手机（adb 或直接传文件安装），打开 App 会看到启动页：

1. **① 我是主机（创建房间）** —— 手机自动在本地起服务端，页面显示「分享地址」；
   点「进入牌桌」就是房主本人上桌（点「复制地址」发给朋友）。
2. **② 加入房间（朋友用这个）** —— 朋友也装同一个 APK，打开后填房主给的地址，
   点「连接并进入」即可；点「搜索附近房间」还能**自动发现**同一 WiFi 下的房间。
   **朋友全程不需要打开浏览器。**

> 手机当主机时，请到系统设置里给本应用开**「允许后台运行 / 无限制省电」**，
> 否则锁屏后可能被系统杀掉（这是安卓的限制，不是 App 的 bug）。
>
> 如果自动检测到的地址不对（比如有虚拟机网卡），房主可以在大厅点地址旁边的「改」，
> 从候选列表里挑一个，或者直接填樱花映射出来的公网地址。

### 玩家怎么进

打开 App → （朋友选「加入房间」填地址）→ 填昵称 → 进入房间。
**人数凑够 2~4 人后房主点「开始游戏」**；只有你一个人时，点「＋ 添加机器人」也能直接开局。

## 二、远程联机（樱花映射）

你电脑上**已经装好**樱花映射启动器（`C:\Program Files\SakuraFrpLauncher`，且有隧道配置），
所以只要加一条指向本机 8080 的隧道即可：

1. 先按「方式 A」把服务端跑起来，确认 `http://127.0.0.1:8080/` 能打开；
2. 樱花映射管理面板 → **创建隧道**：
   - 类型：**TCP**
   - 本地地址：`127.0.0.1`，本地端口：`8080`
   - 节点随便选一个延迟低的
3. 在启动器里启用隧道，日志里会给出**远程连接方式**，形如：
   `xxx.natfrp.com:12345`
4. 把地址告诉朋友，让他们在**同一个 App** 里选「加入房间」，填
   **`xxx.natfrp.com:12345`**（不带 http:// 也行，App 会自动补）。
   房主也可以在大厅点地址旁的「改」，把这个公网地址填进去，朋友直接复制即可。

因为**网页和 WebSocket 走的是同一个端口**，所以只要这一条隧道、一个地址就够了。
前端会自动把 WebSocket 连到 `ws://<当前地址>/ws`。

> 说明：纸牌游戏每条消息只有几十字节，免费节点的带宽完全够用。
> 隧道类型选 **TCP**（不要选"网站"类型，TCP 最省事）。

## 四、玩法规则（对齐原作《Liar's Bar》纸牌模式）

| 规则 | 实现 |
|---|---|
| 牌堆 | Q×6 + K×6 + A×6 + **小丑牌×2** = 20 张，每轮每人发 **5 张** |
| 目标牌 | 每轮从 Q/K/A 里随机指定一张；**小丑牌是万能的，可当任意目标牌** |
| 出牌 | 每回合可出 **1~5 张**，且必须是手里真有的牌（服务端强校验） |
| **不要（过牌）** | 轮到自己时可以不打牌，把机会交给下家；**上家的牌仍留在桌上，下家照样能质疑它** |
| **两圈作废** | 动作数（出牌+过牌）转满 **两圈**（≥2×存活人数）都没人质疑 → 本轮作废、重新发牌，**谁都不用挨枪** |
| 质疑 | **只有当前回合的玩家**能质疑**上家**（最近出牌的人） |
| 判定 | 上家打出的牌里**只要有一张**既不是目标牌也不是 J，就算欺骗 |
| **质疑成功** | 出牌的人对自己开枪，**并且下一轮由成功质疑者先出**（鼓励质疑） |
| 质疑失败 | 质疑的人对自己开枪，下一轮由他先出 |
| **判定锁** | 质疑结算整段演出（异议→亮牌→左轮，约 **7.4 秒**）期间，谁都出不了牌；播完自动解锁 |
| 左轮 | 每人一把，6 个弹位 1 发实弹，**弹位固定，第 1~6 次扣扳机必中一次**；界面显示 `x/6` |
| 出完手牌 | 该玩家本轮被跳过；所有人都出完则本轮自然结束 |
| **观战** | 被淘汰后仍能看牌桌（继续收 state），但**不能发言**（`dead-cannot-chat`），下局才恢复 |
| 胜负 | 场上只剩 **1 名存活玩家** 时结束，他获胜（胜利面板等开枪动画播完才弹出） |
| 人数 | **2~4 人**，房主点开始即开局；机器人偶尔也会过牌 |
| 出牌张数 | 每个出牌组前面会显示「**N 张**」小牌子，一桌人都看得清谁出了几张 |

补充说明（相对原作的适配）：
- 原作是 4 人桌，2~3 人是我们做的适配：仍然每人发 5 张，剩下没发到的牌留在牌堆里不用。
- 原作还有一个「魔鬼牌（红牌）」模式，本版**未实现**。

### 想换异议语音？

直接替换这个文件即可（服务端和 APK 都用它，改完重新打包就行）：

```
core/src/main/resources/web/audio/objection.mp3
```

当前这版是从你给的成步堂录音里**截取的前 2.99 秒**（24kHz 单声道，36KB）。
页面的加载顺序是：**优先播这个录音** → 没有就找系统日文语音朗读 → 再不行才用合成吼声兜底。

### 演出节奏想再改？

都在 `web/js/app.js` 顶部的 `ANIM_HOLD` 里（单位毫秒）：

```js
var ANIM_HOLD = {
    doubt: 2100,        // 「異議あり！」停留多久
    reveal: 2000,       // 亮出被质疑的牌停留多久
    shot: 3000,         // 左轮转轮这一段总共占多久
    play: 650,
    other: 420
};
var SHOT_SPIN_MS = 1300;   // 转轮旋转本身转多久，然后才响枪
```

改完重新打包即可（网页和 APK 会一起生效）。

## 五、安全 / 反作弊

服务端**不再信任客户端**，以下都在服务端校验并返回错误码：

- 越位出牌（`not-your-turn`）
- 出牌数量不是 1~5 张（`bad-card-count`）
- 打出手里没有的牌 / 重复下标（`card-not-owned`）
- 本轮没人出牌就质疑、质疑自己、质疑已离场玩家（`nothing-to-doubt`）
- 非房主开局（`not-host`）、对局中加入（`game-in-progress`）、超员（`room-full`）

### 2.3 真机适配（`tools/sweep-devices.ps1`）

手机上最容易出问题的不是逻辑，而是**横屏时 CSS 视口只有 ~780×360**（1080p、dpr≈3），
比模拟器/桌面小一半以上，布局很容易把按钮挤出屏幕。项目里带了一个机型回归脚本：

```powershell
powershell -ExecutionPolicy Bypass -File tools\sweep-devices.ps1 -WithGame
```

它会逐档修改模拟器的「分辨率 + dpi + 系统字体缩放」，重启 App，
再读页面自己打的布局自检日志（`web/js/uicheck.js` 会把每个关键控件是否**在屏内**、
是否**真的点得到**报出来）：

```
[layout](view) page=/ view=game vp=720x360 checked=11 OK
```

当前 8 档全部通过（含「华为大字体 1.45 倍」和「786×328 极端窄屏」）：

| 档位 | CSS 视口 | 启动页 | 大厅 | 牌桌 |
|---|---|---|---|---|
| 三星 1080p@dpr3 | 720×360 | OK | OK | OK |
| 华为 1080p@dpr2.75 | 786×393 | OK | OK | OK |
| 华为 + 系统字体 1.45 | 786×393 | OK | OK | OK |
| 小米 1080p@dpr2.5 | 864×432 | OK | OK | OK |
| 老机型 1080p@dpr2 | 960×540 | OK | OK | OK |
| 小屏 720p@dpr2 | 640×360 | OK | OK | OK |
| 平板 1600p | 1080×800 | OK | OK | OK |
| 极端窄屏 | 786×328 | OK | OK | OK |

针对真机做的具体适配（都在 `web/css/short.css` 和 `MainActivity` 里）：

- **忽略系统字体放大**：`settings.setTextZoom(100)` —— 华为/荣耀默认字号偏大，
  WebView 会把网页文字一起放大，把布局撑破（这是本次真机按钮点不到的根因）
- **严格 1:1 不缩放**：`setLoadWithOverviewMode(false)`
- **禁止系统强制深色**改配色
- **按高度分档压缩**（≤620 / 460 / 430 / 370 / 320px），矮屏改左右两栏
- **安全区**：刘海屏横屏时留出 `env(safe-area-inset-*)`
- **放不下能滚**：内容溢出时可以滚动，不会出现"按钮永远点不到"

### 4. 三个真实存在过的坑（已修复，写在这里免得再踩）

1. **aapt2 在 Windows 上用 `-A` 打包 assets 时把路径分隔符写成反斜杠**，
   APK 里看着有 `assets/web/index.html`，但安卓 `AssetManager` 按正斜杠查找，
   结果服务器对所有资源返回 404。→ 改为用 `tools/pack_apk.py` 自己以正斜杠写入。
2. **build-tools 34 的 d8 会在含"无名参数"（枚举/匿名类构造函数的 mandated 参数）的类上内部崩溃**，
   报 `NullPointerException: Cannot invoke "String.length()" ...`。→ 改用 **build-tools 36 的 d8**。
3. **PowerShell 5.1 按 GBK 读 UTF-8 的 .ps1**，脚本里写中文注释会把下一行代码吞掉。
   → `tools/` 下的 .ps1 **一律只用 ASCII**。

## 七、重新构建

```powershell
# 电脑端 JAR（几秒）
powershell -ExecutionPolicy Bypass -File tools\build.ps1

# 安卓 APK
powershell -ExecutionPolicy Bypass -File tools\sync-web.ps1   # 先把前端同步进 assets
powershell -ExecutionPolicy Bypass -File tools\build-apk.ps1  # 需要 .toolchain 里的 SDK
```

APK 的构建**不依赖 Gradle**（本机 Gradle 发行包一直下载失败），
而是 `aapt2 → javac → d8 → zipalign → apksigner` 手动流水线，全部工具来自：

```
.toolchain/android-sdk/{platform-tools, build-tools/34.0.0, build-tools/36.0.0, platforms/android-34}
```

如果这个目录不存在了，用下面这条命令重新拉取（约 2 分钟，只下必需的三个组件）：

```powershell
python tools\fetch_sdk_components.py .toolchain\android-sdk
```

> `android/` 下同时保留了一份 **Gradle 工程**（`build.gradle` 等），
> 给习惯用 Android Studio 的人；但注意：**这份 Gradle 配置没有在真机上验证过**
> （本机没有 Gradle 发行包），实际出包走的是上面的 `build-apk.ps1`。

安装到手机：

```powershell
.toolchain\android-sdk\platform-tools\adb.exe install -r build\liarbar.apk
```

### 只想让手机当"纯主机"（本机不入座）

```bat
adb shell am start -n com.liarsbar.android/.MainActivity --ez host_only true
```

### 开机自动进桌（少点一下）

```bat
adb shell am start -n com.liarsbar.android/.MainActivity --ez auto_enter true
```

打开启动页后等 **8 秒**自动进桌。故意留这 8 秒：先让朋友或机器人入座，
免得手机第一个进房就变成房主。

## 八、已知限制

| 限制 | 说明 |
|---|---|
| 手机当**远程**主机 | 樱花官方明确不推荐（后台可能被系统杀掉）。**远程建议用电脑当主机**，你电脑上的樱花启动器已经配置好了 |
| 断线重连窗口 | 60 秒。超时后：大厅里直接移除；对局中判为淘汰（否则会卡住整局） |
| 真机验证范围 | 用「分辨率 + dpi + 系统字体」模拟了 8 档机型（含华为大字体、极端窄屏）**全部通过**；但**没有在真机上装过**，个别 ROM 的省电策略仍建议实测一次 |
| 头像存储 | 服务端只在内存里留着，App/主机重启后靠**手机本地那份自动补传**；如果换设备登录，需要重新选一次 |
| 前端缓存 | 服务端对 html/js/css 发了 `no-store`，改完刷新就是最新的 |
| 魔鬼牌模式 | 未实现 |

## 九、原 Spring Boot 版怎么办

原工程（本文件夹根目录的 `pom.xml` / `src/`）**保持原样**，只顺手修了两处**让它至少能编译运行**：

1. `src/main/java/.../message/Msg_Client/Doubt.java` → 重命名为 `DOUBT.java`
   （原来文件名和 `public class DOUBT` 不一致，javac 直接报错，`mvn compile` 必失败）；
2. `src/main/resources/static/JavaScript/WebClient.js` 里写死的
   `ws://localhost:8080/ws` → 改成按当前地址自动推导，这样手机浏览器也能连。

不过原版仍然是**固定 4 人开局**、且没有大厅/断线处理，日常玩建议直接用 `liarbar-v2`。
